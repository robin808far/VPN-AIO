## Findings requiring fixes

P1 means fix before relying on the affected feature for customers. P2 means a confirmed functional defect. P3 is a smaller validation/display defect. Product source was not changed during this review.

### A1 — P1: reseller access exposes other sing-box users' credentials

`web/service/inbound.go:118,204` filters only the Xray `clients` array. A raw sing-box inbound carries credentials in `users`, which passes through unchanged. A new reseller with a grant to the shared inbound and **no owned accounts** received its house user's UUID from `/panel/api/inbounds/list`.

Evidence: `extended.json`, `TestReview610SingboxFiltersResellerUsers`. Scope the sing-box users to account ownership, or refuse to expose unmanaged raw user blocks to resellers until that ownership exists.

### A2 — P1: sing-box bypasses the account and traffic/limit integration

`web/service/inbound.go:534` reads `clients`, while `singbox.go:71` runs raw `users`. `web/job/xray_traffic_job.go` has no sing-box collection or enforcement adapter. A real VLESS sing-box tunnel transferred more than 128 KiB through an inbound with a **1 KiB quota**; usage remained zero, the user never appeared in Clients, and another transfer still succeeded. The bundled sing-box build also lacks `with_v2ray_api`.

Evidence: `features.json`. Implement identity/account projection, collection and enforcement together. Until then, the panel must clearly represent the limits it can actually enforce.

### A3 — P1: the sing-box GUI sends Xray settings and loses saved data on edit

`web/html/modals/inbound_modal.html:281,979` stores the editor draft on `inboundModalVueInstance.singboxDraft`. `web/html/inbounds.html:1342,1384` reads `inModal.singboxDraft`, which is undefined. Capturing the actual Add method showed `core="singbox"` with Xray `clients/decryption/encryption` settings and no raw users.

Separately, `web/assets/js/model/dbinbound.js:166` omits `core`; `web/assets/js/model/inbound.js:3363` parses raw settings through Xray classes, and `toJson():3415` omits `core` again. Opening a valid sing-box inbound showed Xray as the core and dropped its `users/type/listen_port` fields. A save can corrupt the stored inbound.

Evidence: `browser-findings.json`, captured directly in Chromium against the exact release.

### A4 — P1: create/edit reconciles sing-box before the transaction commits

`web/service/inbound.go:1474,1506,1748,1864,1909` invokes `RestartServices()` while the new row is uncommitted, or before the updated row has even been saved. `GetSingboxInbounds()` uses a separate DB handle and sees the old state. New inbounds did not start until a manual restart; editing the listen port left the old listener active.

Evidence: `features.json`. Reconcile after successful commit, using the correct committed inbound. The current call also restarts every sing-box inbound during an unrelated inbound edit.

### A5 — P1: invalid sing-box configurations are accepted as successful saves/restarts

`web/service/singbox.go:71,185` does not validate before persistence and logs generation/check/start failures while returning nil. The API accepted an enabled inbound with `type="not-a-protocol"`.

The GUI defaults additionally generate configurations rejected by the exact bundled core: VMess gets an unsupported `flow` field; Shadowsocks 2022 gets a random non-base64 key; TUIC's initial settings lack required TLS/UUID configuration. Some form controls also write protocol-specific fields without checking the actual sing-box schema.

Evidence: `features.json`, `regression-probes.jsonl`. Validate the prospective full config before committing, return real errors, preserve the prior working file/process, and make default forms valid or explicitly incomplete.

### A6 — P1: returning to Inbounds through soft navigation breaks its modal

`web/assets/js/softnav.js:67,83,140` cannot repair lexical bindings already created on a normal page load. `web/html/modals/inbound_modal.html:83,98,104,255` still declares top-level `const`/`let`. Navigate Inbounds → Nodes → Inbounds: Chromium reports `Identifier 'INBOUND_SECTIONS' has already been declared`; Add sets `visible=true`, but the retained modal Vue instance is detached, the new `<a-modal>` is unmounted, and no dialog appears. Repeated vendor evaluation also produced an OTPAuth redeclaration error.

Evidence: `browser-findings.json`. Fix the complete page lifecycle and its declarations; catching/logging the error does not restore the modal.

### A7 — P1: Persian mobile forms render their input pane off screen

`web/assets/css/components.css:2874` forces `[dir="rtl"] .bo-cf` to `row-reverse`, overriding the mobile column layout at line 1381. At a 388 px iframe viewport, the 372 px modal had a **758.7 px rail**, and its **32 px input pane started at x=766.7**. The Identity section had zero width. The form was effectively blank on screen.

Evidence: `browser-findings.json`, `persian-mobile.png`. Restrict the desktop reversal to its intended breakpoint and verify the shared inbound/client rail layout in RTL at phone widths. Desktop Persian font and the initial desktop modal did render.

### A8 — P1: core uninstall silently strands sing-box inbounds

`web/service/corecatalog.go:471` never counts sing-box inbounds. `coreuninstall.go:98` trusts that count, while `deleteCoreInbounds():123` maps by protocol and ignores `Inbound.Core`. With one enabled sing-box VLESS inbound, the catalog reported zero; `/panel/core/uninstall` accepted the removal **without an inbound disposition**, removed the binary, and left the inbound enabled in the DB.

Evidence: `core-uninstall.json`. This destructive reproduction ran only in the disposable review container. Fix both counts and engine-aware ownership in the uninstall paths.

### A9 — P1: the Nodes UI cannot mint its API token

`web/controller/node.go:144` declares only JSON tags for lowercase `name/scopes`; the UI at `web/html/nodes.html:257` submits form-encoded data. The exact UI payload returned `token name is required`; a JSON control request succeeded. Add the corresponding form bindings or a separate correctly bound request type.

Evidence: `features.json`. Bearer authentication, scope rejection, revocation, prefixed remote probing and summary reads passed once a token was minted with JSON.

### A10 — P2: the API reports an engine change that was not persisted

`web/service/inbound.go:1829` copies editable fields to `oldInbound` but never copies `Core`. Both Xray → sing-box and sing-box → Xray update requests reported success while a subsequent GET returned the old core. If changing engines is intentionally unsupported, reject it explicitly instead of acknowledging an unapplied change.

Evidence: `extended.json`.

### A11 — P2: the new sing-box share-link generator is incomplete and unsafe to rely on

`sub/subService.go:2435` ignores the requested email and always uses `users[0]`. Direct regression probes also demonstrated missing WebSocket path/Host, REALITY incorrectly exported as ordinary TLS without its key/short ID, a panic when optional Hysteria2 `obfs` is absent, and an extra leading colon in Trojan credentials. TLS block presence is treated as enabled regardless of `tls.enabled`.

Evidence: `regression-probes.jsonl`. These are **direct generator probes**, not a claim that the currently incomplete raw-user subscription path already delivers these links over HTTP. Complete account selection and format-specific exports before enabling that path.

### A12 — P2: saving sing-box base settings fails on a fresh installation

`web/service/singbox_base.go:158` writes `/etc/vpn-ui-singbox/.base-check.json` without creating the directory. A fresh save failed with ENOENT; the same save worked after creating an inbound. Use a private temporary validation file in an ensured directory.

Evidence: `features.json`. As a smaller validation gap, `mergeBaseConfig("null")` is accepted as an object (direct regression probe).

### A13 — P2: node renaming is ignored

`web/service/node_service.go:72` updates scheme/address/port/base path/token/etc., but never assigns `node.Name`. The update response retained the original name. Token preservation on a blank edit did work.

Evidence: `features.json`.

### A14 — P2: bare IPv6 node addresses produce invalid URLs

`web/service/node_service.go:195` concatenates `address + ":" + port`; `2001:db8::1` becomes `http://2001:db8::1:8443/...`. Use `net.JoinHostPort` with correctly normalized input.

Evidence: `TestReview610NodeIPv6URL` in `regression-probes.jsonl`.

### A15 — P2: soft navigation retains old WebSocket callbacks

`web/html/inbounds.html:1894` installs anonymous WebSocket callbacks without removing them at destruction. Because soft navigation now retains the document and shared `wsClient`, revisiting Inbounds increased each inbounds/traffic listener count from **1 → 2 → 3**. Old Vue instances keep receiving events and invalidate callbacks can repeat HTTP work.

Evidence: `browser-findings.json`. Dispose listeners, timers and separately mounted modal instances with the page.

### A16 — P2: manual release dispatch does not select its requested source tag

`.github/workflows/vpn-aio-release.yml:21` checks out the workflow/default ref; `inputs.tag` is used only for changelog/publication. Dispatching an older tag from main can therefore publish main's binary under that older tag. This is a static workflow finding. The current 6.1.0 run used `60951c62`; comparison with its tag confirms that this particular release has identical runtime source.

### A17 — P3: sing-box version is blank in Core Settings

`web/service/core.go:242` invokes every daemon with `--version`; sing-box 1.12.14 uses the `version` subcommand. The installed binary works and prints 1.12.14, while status reports an empty version. Special-case the daemon's supported invocation.

## Boundaries and next work

- Nodes currently provides registration, status/probe/heartbeat and remote summary reads. Remote inbound/client mutation and traffic synchronization are **not implemented**, as the previous handoff already noted. TLS pinning/mTLS and sub-node trees are also outstanding.
- This review did not add product fixes, push commits, republish releases or replace the live panel binary. The supported live Xray profiles continued to work. Keep customer usage on the verified path while fixing sing-box integration.
- No real ARM machine, every distro boot/kernel combination, or external mobile VPN clients for every native protocol were tested. Native protocol config/unit checks are not a claim of device-level coverage for all of them.
- Recommended implementation order: A1/A2 security and account enforcement; A3–A5 sing-box data/transaction/validation paths; A8 uninstall ownership; A6/A7/A15 UI lifecycle and responsive RTL; then Nodes and export fixes. Add regressions that exercise HTTP form binding and browser round trips.
